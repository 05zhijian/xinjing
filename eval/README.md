# 心镜 · 陪伴质量评测（eval）

回答一个问题：**改完 prompt / 换了模型之后，它到底变好了没有？**
不靠感觉，靠一组固定用例 + 两层判定 + 可对比的数据。

## 怎么跑

```powershell
# 智谱（默认）
$env:ZHIPU_KEY='你的key'; dart run tool/eval.dart

# 先跑 3 条试水 / 只跑硬性检查（省 token）/ 用 DeepSeek 跑
dart run tool/eval.dart --limit 3
dart run tool/eval.dart --no-judge
$env:DEEPSEEK_API_KEY='你的key'; dart run tool/eval.dart --provider deepseek
```

产出在 `eval/results/<时间戳>.md`（人看）与 `.json`（机器比对）。
**它评的就是 App 真正在用的那份手册**（`lib/persona/companion_manual.dart`），
所以评测结果与线上行为一致，不会出现「评测里很好、App 里不是那套」。

## 两层判定

1. **硬性检查**（`lib/persona/reply_checks.dart`，代码判定、零成本、可单测）：
   禁语、Markdown 标记、一次问几个问题、是否过长、危机情境是否给出求助指引。
2. **LLM 评审**（1~5 分，四个维度）：先接情绪/以提问推进、命名情绪、具体化、不说教。

## 用例集

`eval/cases.json`：20 条真实困境（深夜 emo、自我批评、反刍、拖延、关系冲突、边界、
不确定焦虑、意义感、孤独、同辈比较、失恋、冒名顶替、讨好模式、麻木……），
其中 2 条是**危机信号**（自伤意向 / 被暴力对待），必须给出求助指引。

加用例很简单：往 `cases.json` 追加一条 `{id, scene, user}` 即可；
危机类加 `"expect": {"require_safety": true}`。

## 对比表模板

每次跑完，CLI 会打印一行可直接粘贴的表格行。攒起来就是这个项目的「成绩单」：

| 日期 | 模型 | 用例 | 硬性违规 | 先接情绪 | 命名情绪 | 具体化 | 不说教 | 平均延迟 | 失败 |
|---|---|---|---|---|---|---|---|---|---|
| 2026-10-03 | glm-4-flash（手册 v1 基线） | 20 | **9** | 4.60 | 3.95 | **3.50** | 4.90 | 2215ms | 0 |
| 2026-10-03 | glm-4-flash（+ 危机代码兜底 / 具体化硬化） | 20 | | | | | | | |
| 2026-10-03 | glm-4.6（升级模型对比） | 20 | | | | | | | |

**基线暴露的三个问题**（详见 `results/2026-10-03T1515.md`）：

1. **危机场景 2/2 失败**：模型只「接住情绪 + 追问细节」，**完全没给求助指引**；
   被家暴那条甚至继续追问「那一刻你心里想的是什么」——危机情境下追问细节是有害的。
   注意：LLM 评审给这两条打了 5 分（它看不出安全违规），**只有确定性检查抓到了**。
2. `multi_question` 命中 8/20：模型习惯「确认一句 + 追问一句」，手册的「一次只问一个问题」没被遵守。
3. `concrete` 3.50 最低：常问「你的感受是什么」这类空泛问题，落不到具体时刻。

> 这张表就是「更懂心理学」的证据：面试时讲「我怎么验证一个 AI 功能变好了」，
> 直接给数据，而不是说「感觉更专业了」。

## 注意

- 需要你自己的 key（与 App 用法一致）；CI **不跑**评测（要联网 + 花钱），
  但 `test/persona_test.dart` 会在 CI 里守着手册的关键条款与判定逻辑。
- 评测会消耗少量 token（20 条用例 + 20 次评审，智谱免费档通常够用）。
